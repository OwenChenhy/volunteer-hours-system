# 旧复核队列结案与统计修复

## 原因

最终累计成绩单已经逐人核定，但导入验收遗漏了旧记录的复核队列。仍显示的186条全部来自旧5月库，原问题类型及未处理标记一直保留。页面还将所有非正常类型都放进“问题状态分布”，把累计校准、推算和余额记录混成待办；顶部“待复核问题”也包含已处理条目。

## 逐条核对与结案依据

对11份旧工作簿的186条原始总时长单元格进行了独立读取，数值与对应库记录全部一致。

| 分类 | 条数 | 处理依据 |
| --- | ---: | --- |
| 最终成绩单已核定 | 114 | 身份匹配最终导入对象，当前累计与9月最终核定逐人一致，关闭旧明细拆分待办 |
| 接受旧累计 | 30 | 不在本次9月清单中，但原5月单元格、库记录、当前个人累计三者一致，按已确认的累计口径结案 |
| 范围外归档 | 42 | 学号第二三位小于21，按用户范围规则归档，不据此声称旧明细已经核准 |

每条写入独立复核凭据，保留原问题类型、来源文件/工作表/行/单元格、文件摘要、数值与结案理由。归档与确认分别记录，不删除旧记录，不修改学生正式时长或公示。

## 程序修复

复核列表、未处理筛选、工作台及统计使用同一处理状态计算：已有处理标记，或明确的确认/范围归档凭据，均退出未处理队列。普通备注不会关闭问题；凭据仅对其对应记录生效。

页面区分“待复核问题”“已处理及归档”“待处理冲突”。默认筛选只展示未处理；已结案与范围外记录仍可单独检索。状态分布只展示真正的复核类型，不再把正常累计校准、推算和余额类型当作待办。

## 验证与维护

已先复现旧接口返回186条未处理、141条冲突，并以真实接口回归证明旧程序会把有结案凭据的记录继续列为未处理。修复后，结案、归档、普通备注、新冲突、工作台计数、类型筛选及列表筛选均通过真实SQL验证。

结案操作只新增复核与操作审计。七张核心业务表、公示指针、冻结快照及数据版本摘要必须保持；重复执行不得新增重复凭据。专用隔离测试库为 `volunteer_review_fix_test_20261019`，禁止将夹具连接生产。

回归入口：`npm --prefix backend run test:review-closure`，提供上述隔离库的 `DATABASE_URL` 和临时 `JWT_SECRET`。既有后端六组回归及管理端服务器构建也须通过。

私有逐条证据与生产验收结果保存在服务器 `/opt/volunteer-system-review-status-checks-20261019/`，不提交公共仓库。
