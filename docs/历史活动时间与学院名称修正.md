# 历史活动时间与学院名称修正

日期：2026-10-13。范围：现有历史库，后续导入继续走审核和统一发布流程。

状态：2026-10-13 01:48（北京时间）发布和镜像同步完成。主站、主库与镜像当前版本已核对一致，公开状态接口为 `ok`。

## 原因

旧离线脚本 `tools/prepare-march-public-detail-import.js` 的 `activityDateForPeriod()` 把表头的上半年转换为12月31日、下半年转换为6月30日，单个年份也转换为12月31日。`statsService.getByMonth()` 按这列日期直接统计，造成历史库看似有准确的月份，甚至出现2026年12月的未来记录。原始表中的期间说明不能证明活动的具体发生日期。

例如，导入的“2025-2026上半年”列被写成2025-12-31，随后被统计到2025年12月。这是占位日期，不是12月真实活动次数。

学院名称归一化漏掉“计科学院”“计科”“数科学院”“化工”，使同一学院在汇总中被拆成多行。

## 本次修正

- 现有34,277条志愿记录的活动日期清空；5,239个活动的开始、结束时间清空。
- 现有记录的期间说明统一为“2026年10月之前导入的活动”，取消按占位日期推算的学年和阶段。
- 真实导入及审计时间 `created_at` 保留；未改写学号、姓名、年级、时长、审核状态和来源定位信息。
- 管理端月份统计将旧库归入一个历史范围；历史累计汇总和同学院同年级排名仍可查询。
- 管理端活动编辑、问题复核和学生记录更正允许历史日期留空；新增活动仍须真实开始、结束时间，新导入仍须提供或明确填写活动日期。
- 新导入的导入时间由服务器生成，查询接口单独返回 `imported_at`，不将导入时间充当活动发生日期。
- 主库修正后重新生成正式发布快照，避免只修改管理端而让学生查询仍读取旧日期、旧学院名。
- 主库及Supabase镜像日期列允许空值，镜像继续保持原有RLS及服务端访问方式。
- 镜像原本通过一个REST请求上传整份发布快照，约24MB的单版本请求和约48MB的多版本请求出现HTTP 520。现在按不足700KB分块上传，仅服务器角色可调用；记录数、总时长和完整快照摘要核对一致后标记完成，再同步当前发布指针。已经完成的冻结版本不重复上传。

## 操作口径

学生查到的历史活动统一显示“2026年10月之前导入的活动”，可查看历史累计和排名。管理员以后导入活动时，填写真实活动日期，系统记录导入时间；办公室完成审核后统一发布。历史记录不会自动归入当月或当前学年。
