# 历史分类恢复

当前阶段：服务器隔离验收全部通过，准备发布代码并执行有备份和审计保护的分类恢复。生产结果将在文末追加。

用户澄清：只抹除具体发生日期和占位时间戳；寒暑假、各学年的上半年及下半年必须保留。此规则取代此前把全部历史期间并入单一历史范围的做法。

根因有三处：旧时间清理和最终累计导入清空了分类字段；SQL分类先检查日期为空，把有明确表头归属的记录当作未归类；导出要求寒暑假也必须有明确学年，未注明学年的寒暑假被挪进备注。原有页面还把未知学年汇总折叠成一个累计列。

恢复仅改真实活动记录的 activity_period、academic_year、academic_term，不恢复占位日期，不改变活动名称、学生身份、小时数、累计依据、复核结案及旧冻结公示。33,702条真实活动逐ID与2026-10-12清理前备份对齐，再核对13份只读五月原表的工作表、原行和表头。逐条来源坐标及源文件摘要保存在服务器受限目录，个人数据不进入仓库。原表的重复同名栏目按同一原分类处理，不擅自把其中一个“上半年”改成“下半年”。

1913条成绩单差额与575条原表未拆分累计没有可靠阶段依据，继续保持非活动账目，不按差额大小、导入日期或当前学年猜测归属。9月最终累计仍只作为已人工确认的累计控制值，不再次整表追加时长。只有原表明确的分类被恢复；原始材料里没有的内容不补造。

公共查询、管理员查找、学年汇总及公示导出共同保留原分类。没有学年但明确是寒暑假的记录仍显示寒暑假。模板没有相应阶段栏目时保留带原学年阶段标签的备注，不能塞入相邻阶段。旧公示版本按其冻结内容导出，不回写旧快照；修复后的分类通过新公示版本发布。

离线清理脚本也改为只清理实际日期字段，并将源分类纳入完整性校验，避免今后再次清空分类。专用回归命令：npm --prefix backend run test:period-categories，只允许连接任务隔离库 volunteer_period_test_20261019。

本次开发、构建、测试及浏览器验收均在服务器完成；未调用DeepSeek或其他模型API，未新增依赖。完整恢复清单、红绿复现、逐人累计摘要及生产证明目录：/opt/volunteer-system-period-checks-20261019/。

## 隔离验收结果

33,702条真实活动的分类均与清理前备份及13份五月原表相符；全部9,462个学生身份组合的累计逐人相同，36,190条账目总计355,249.9小时，所有发生日期仍为空。除三个分类字段外，全库记录内容摘要保持相同，原186条复核结案及所有旧冻结公示保持。

16份学院Excel的9,462行累计逐人相符；32,719条明细回到匹配的原模板分类列，983条因模板缺少该分类而在原备注或批注里保留学年阶段标签，共15,426个分类单元格恢复内容。寒暑假不因缺少年份被合入未归类项，原表表头及版式没有改动。全部33,702条明细的位置和文字均独立逐条核验。
