# 运维页 Redis 状态修复

2026-10-19。修复在 `codex/redis-ops-status-20261019` 分支完成，待 PR 审核；本项修复尚未部署，本轮没有修改或部署生产代码。

## 问题与行为

学生查询与排名缓存已经生效，但受权限保护的 `/api/v1/ops/status` 没有返回 Redis 字段。页面将缺失信息归为“待接入”，连接及 Key 数均显示空值。

运维接口现复用实际查询缓存的 Redis 连接，通过实时 DBSIZE 获取连接结果和当前数据库的 Key 总数。空库的 0 是正常值；未配置连接显示“未启用”；配置存在但连接或命令失败时显示告警，并明确查询回退数据库。连接恢复后告警自动消失，沿用现有连接 1 秒、命令 500 毫秒及失败重试间隔，不增加依赖或配置项。

状态接口与 `/monitoring` 别名均返回 `Cache-Control: no-store`。权限仍限管理员、超级管理员、数据管理员和审计员，学院管理员与组织者不可访问；响应只含状态、Key 总数和检查时间，不包含 Redis 连接串、认证信息、键名或学生数据。

页面的“需关注项”改为全部非健康卡片数量，修复原先遗漏 `warning` 等状态的情况。
