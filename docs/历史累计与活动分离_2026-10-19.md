# 历史累计与活动明细分离

状态：隔离迁移、逐人总数核对、业务回归及桌面/手机页面检查已通过，待发布后补生产证据。

旧导入把最终成绩单与已有明细之间的差额写成了名为“最终累计成绩单校准”的活动。这不是实际发生的活动。另有旧源表只提供累计数的记录，曾挂在“累计时长记录”占位活动下。两种情况都应作为时长账目保存，不应生成活动名称或活动编号。

`volunteer_logs.record_kind` 区分真实活动 `activity`、成绩单差额 `historical_balance`、原表累计项 `historical_cumulative`。时长汇总与排名仍计算所有有效账目；活动列表、活动明细、活动数量和活动排行只计算 `activity`。累计项的活动名称、活动关联和发生时间归属为空，查询页与管理员学生查找单独展示累计依据。累计项不能通过活动修改、撤回、作废或恢复入口改变。

此次识别了 1,913 条成绩单差额和 575 条原表累计项。原表累计项迁移前的完整记录、关联占位活动保存于 `operation_logs` 的 `hours.classify_legacy_cumulative` 审计事件；原始文件、工作表、行号、核定累计和导入批次继续保留。仅删除一个已无任何记录引用的累计占位活动。真实活动及学生身份不改动。

公示 Excel 保留原学院模板结构，累计总数照常输出；原表累计项和成绩单差额以明确的非活动说明写入备注（没有备注列的模板使用原累计单元格批注）。旧公示快照保持原始内容不变，读取和导出时按原导入类型识别累计项，避免把旧技术名称再次当成活动展示。新公示保存明确的记账类型。公共查询缓存使用新的版本前缀，隔离旧响应结构。

迁移文件 `backend/src/db/migrations/008_historical_balances.sql` 随后端启动执行；重放不会重复迁移、重复记审计或增加账目。数据库约束禁止累计项带活动名称/编号/发生时间，禁止同一来源同一学生重复记入同类累计项。Supabase 镜像仅增加类型字段并允许累计项的活动名称为空，数据由主库同步，不在备库独立推断。

已验证：全部 9,462 个学生身份组合累计时长不变，36,190 条账目共 355,249.9 小时；33,702 条真实活动记录完整内容不变，575 条累计来源字段和 1,913 条差额来源字段不变；原有复核结案和历史公示不变。隔离的真实活动提交、审核、发布验证从核定 6 小时增加 2.5 小时后得到 8.5 小时，重复提交被拒绝。新增专用回归命令：`npm run test:historical-balance`，仅允许任务专属隔离数据库。

生产发布与核对证据会追加在本文件末尾；包含学生信息的逐条证据仅存于受限工作目录，不提交仓库。
